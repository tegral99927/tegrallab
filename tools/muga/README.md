## 1. 概要

Mugaは、瞑想の達成や精神状態の改善を保証するツールではありません。  
ユーザーが目を閉じ、音楽に身を委ねることで、思考や自己意識が自然に静まる可能性を提供する、ミニマルな音楽体験ツールです。

- **技術スタック**: HTML5, Vanilla CSS, Vanilla JavaScript（ES6+）, Web Audio API
- **ビルド不要**: トランスパイルやバンドル（Vite, Webpack等）を一切行わず、静的ファイルのみで動作します。
- **レスポンシブ対応**: スマートフォン、タブレット、PCに対応したユニバーサルデザイン。
- **プライバシー配慮**: 外部API通信、追跡用DB、ログイン機能、Cookie保持などは行いません。

## 2. 開発思想

### 「何かを達成しようとしないこと」

東洋哲学の「無我」「無為自然」「空」に着想を得ていますが、特定の宗教的実践や儀式を要求するものではありません。

本アプリケーションでは、以下の要素を**一切実装していません**：

- 瞑想の連続達成日数（ストリーク）
- ポイント・レベル・ランク
- 実績バッジ・スコア
- 瞑想時間の累計表示やタイマーカウントダウン
- 「無我になれたか」の達成判定や自己評価
- 他人とのスコア比較・ランキング
- SNSへのシェアを催促するポップアップ
- 有料プラン・課金導線

音楽を聴くこと自体が目的であり、何かを感じる必要も、特別な精神状態に至る必要もありません。  
音が流れ、音が消え、静けさが残る。その静寂をそのまま受け入れるための空間です。

## 4. 音声ファイルの追加方法

Mugaで再生したいアンビエント音楽やドローン音源、フィールドレコーディング等の音声ファイルを `music/` フォルダ内に配置します。

### 対応する音声形式
- **MP3** (`.mp3`) — 最も推奨される汎用フォーマット
- **WAV** (`.wav`) — 非圧縮高音質フォーマット
- **OGG** (`.ogg`) — 高品質オープンフォーマット
- **M4A / AAC** (`.m4a`) — ブラウザ（特にSafari/iOS）対応フォーマット

> **重要なお知らせ**  
> 静的Webサイトのセキュリティ制限により、ブラウザ上のJavaScriptはサーバー側フォルダ内のファイル一覧を自動スキャンすることはできません。  
> そのため、**ファイルを配置しただけでは再生対象になりません**。必ず次の「5. playlist.jsonの更新方法」に従ってファイル名を登録してください。

---

## 5. playlist.jsonの更新方法

`music/playlist.json` をテキストエディタで開き、`music/` フォルダ内に配置したファイル名を配列として記述します。

### 記述例

```json
[
  "muga_shizuku.wav",
  "muga_ku.wav",
  "muga_nagare.wav",
  "my_ambient_track01.mp3",
  "nature_waves.mp3"
]
```

### 再生ルール
- 配列に登録された曲の中から、再生ボタンが押されるたびに**ランダムに1曲**が選ばれます。
- **1曲だけ登録されている場合**も正常に動作します。
- 同じ曲が連続して選ばれる可能性を許容しています。
- 曲の終了後は**自動で次の曲を再生しません**。静寂の状態を保ちます。

## 6. ローカルでの動作確認方法

`fetch` API を用いて `music/playlist.json` を読み込むため、`index.html` をブラウザに直接ドラッグ＆ドロップ（`file://` プロトコル）すると、ブラウザのCORSセキュリティ制約によりファイル読み込みがブロックされる場合があります。

必ずローカルHTTPサーバー経由で確認してください。

### 方法A: Python を使用する場合（推奨・追加インストール不要）

PowerShell またはターミナルを開き、本リポジトリのルートまたは `tools/muga/` ディレクトリで以下を実行します：

```bash
# tools/muga ディレクトリで実行する場合:
cd tools/muga
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます。

### 方法B: Node.js (npx serve) を使用する場合

```bash
npx serve tools/muga
```

表示されたローカルURL（例: `http://localhost:3000`）を開きます。

### 方法C: VS Code / IDE の拡張機能を使用する場合
「Live Server」などの拡張機能をインストールし、`index.html` を右クリックして「Open with Live Server」を選択します。

## 7. 静的ホスティングへの公開方法

ビルドコマンドは不要です。`tools/muga/` 内の全ファイルを静的ホスティングサービスの公開ディレクトリへそのまま配置・デプロイしてください。

- **GitHub Pages**: リポジトリをプッシュし、Settings > Pages から該当ブランチまたはフォルダを指定。
- **Cloudflare Pages / Vercel / Netlify**: ビルドコマンドなし（None）、公開ディレクトリ（Root Directory）を指定してデプロイ。
- **Apache / Nginx / 独自サーバー**: Webルート配下にファイルをそのままアップロード。

## 8. 公開URL設定とSEO関連ファイルの更新方法

本テンプレートでは、仮の想定ドメインとして `https://tegrallab.com/tools/muga/` を設定しています。  
独自ドメインやサブディレクトリが決定した際は、以下の箇所のURLを本番URLに差し替えてください。

1. **`index.html`**:
   - `<link rel="canonical" href="https://your-domain.com/">`
   - `<meta property="og:url" content="https://your-domain.com/">`
   - `<meta property="og:image" content="https://your-domain.com/assets/ogp.png">`
   - `<meta name="twitter:image" content="https://your-domain.com/assets/ogp.png">`
   - JSON-LD 内の `"url": "https://your-domain.com/"`
2. **`robots.txt`**:
   - `Sitemap: https://your-domain.com/sitemap.xml`
3. **`sitemap.xml`**:
   - `<loc>https://your-domain.com/</loc>`

## 9. 対応ブラウザと制限事項

### 対応ブラウザ
- **PC**: Google Chrome, Mozilla Firefox, Apple Safari, Microsoft Edge（各最新版）
- **スマートフォン・タブレット**: iOS Safari (iOS 14+), Android Chrome

### 動作仕様とブラウザの制限事項
1. **自動再生ポリシー**:
   - 各種ブラウザ（特に iOS Safari および Chrome）では、ユーザーの明確なタップ/クリック操作がない状態での音声自動再生は制限されています。本アプリはユーザーが「音を聴く」ボタンを押した契機でのみ再生を開始するため、この制限に準拠しています。
2. **バックグラウンド再生・スリープ中の再生**:
   - モバイルOS（iOS / Android）の仕様により、画面がロックされたり別タブ・別アプリに移動した場合、ブラウザの省電力機能により音声が一時停止する場合があります。これはOS側の制約によるものです。
3. **フェード処理**:
   - 再生開始時: 約3秒かけて滑らかにフェードイン。
   - 停止ボタン操作時: 約3秒かけてフェードアウトしたのちに静止。
   - 音源の自然終了時: 終了前約5秒間から自然にフェードアウトし、終了後に完全な静寂へ移行。
   - iOS Safari 等の `<audio>.volume` 制御制約に対応するため、Web Audio API の `GainNode` を優先利用し、必要に応じてフォールバックするハイブリッド設計を採用しています。
